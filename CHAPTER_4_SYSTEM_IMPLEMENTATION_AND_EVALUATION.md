## Implementation Plan

To transition KinTrace from an experimental codebase into an operational mobile platform for Filipino families, this implementation strategy establishes the technical deployment protocols, cloud infrastructure milestones, and multi-generational onboarding procedures. The rollout framework governs how native Android packages are assembled, how distributed client devices connect to Google Cloud Firebase backends, how historical genealogical records are securely migrated into structured NoSQL document stores, and how comprehensive software verification is conducted across multiple development cycles before broader clan adoption.

### 1. System Deployment

* **Client Application Distribution:** KinTrace is packaged natively as signed Android Application Packages (APKs) distributed through dedicated release channels on GitHub and cloud direct-download endpoints, equipped with an in-app update detector (`InAppUpdateManager`) that prompts users whenever a newer version is deployed. The system's build configuration satisfies all modern target API requirements, ensuring full readiness for Google Play Store publication. The supporting backend is anchored on Google Cloud Firebase under the Blaze Plan, where Cloud Firestore serves as the distributed real-time NoSQL document store. This backbone enables instantaneous synchronization of kinship links, biographical edits, and reciprocal parental records across relatives' smartphones within two seconds of modification. In parallel, Firebase Authentication enforces botanical role hierarchies (Seedling, Sprout, Branch Keeper, and Elder), Firebase Cloud Storage houses historical portrait scans and civil certificates within isolated security rules, and Google Cloud executes automated daily database exports to provide disaster recovery protection.

### 2. Key Implementation Tasks

* **Engineering Environment & UI Framework:** Development activities were centered within Android Studio (Iguana / Hedgehog), employing Kotlin 1.9+ and modern Android Jetpack architecture components (ViewModel, LiveData, ViewBinding, and Lifecycle observers). To overcome the rigid limitations of traditional tree widgets, the technical team engineered custom hardware-accelerated 2D Canvas views (`FamilyTreeView` and `HorseshoeFanChartView`) capable of rendering multi-generational graphs, bendable marriage lines, and dynamic 200-member radial wedges without UI frame drops. Collaborative progress, feature branches, pull request reviews, and commit checkpoints were managed consistently through Git version control on GitHub.
* **Central Repository & Data Synchronization Pipeline:** To preserve relationship consistency across the entire app, the researchers instituted a single source of truth through `FirestoreHelper` and `CentralTreeSynchronizer`. Whenever a user manipulates tree nodes, this pipeline atomically executes reciprocal link updates (such as simultaneously pairing a parent's child list with the child's father/mother pointers and chronologically indexing spouses), entirely eliminating dangling links, orphan records, or out-of-sync screen states.

### 3. Resource Allocation

* **Hardware and Software Infrastructure:** The engineering phase was supported by development workstations featuring multi-core processors, 16 GB RAM, and Windows 11. Cross-device validation utilized physical Android smartphones spanning Android 8.0 (Oreo) through Android 15 (Vanilla Ice Cream) with diverse screen densities, supplemented by Android Virtual Devices (AVDs). The core software suite comprised Android Studio, the Android 14/15 SDKs, Git/GitHub, and the Google Cloud Firebase services (Authentication, Cloud Firestore, Cloud Storage, and Security Rules).
* **Project Roles & Stakeholder Engagement:** Implementation relied on collaborative coordination among the student development team, the capstone adviser, and participating family clans. The student developers handled system design, Kotlin engineering, Canvas algorithms, database schemas, and unit test suites. The capstone adviser provided technical review, software engineering guidance, and manuscript quality audits. Family clan representatives—consisting of designated clan stewards and multi-generational relatives—participated during empirical user evaluation and contributed real genealogical datasets to verify system accuracy under real-world conditions.
* **Educational Resources & Documentation Assets:** To facilitate effortless user adoption across both young and senior relatives, the researchers created self-paced guidance assets. These included the embedded KinAcademy educational portal, the searchable Kamag-anak Lexicon of Filipino kinship terms, universal QuickAssist in-situ drawer sheets on every screen, printed user manuals, and benchmark 20-member and 200-member lineage datasets for testing.

## System Life Expectancy

* **Operating Horizon:** KinTrace is architected for a sustainable minimum operating horizon of **3 to 5 years**. This operational duration corresponds to standard mobile OS lifecycle maintenance windows and the three-year fiscal projections established in the project's economic feasibility study. Throughout this period, the application can reliably support the genealogical documentation, relationship validation, real-time collaboration, and archival management requirements of multi-branch Filipino family clans without fundamental refactoring.
* **Technology Longevity & Platform Support:** By adopting modern native Kotlin engineering and official Android Jetpack architecture components backed by Google Cloud Firebase, the system is insulated against rapid software obsolescence. The underlying libraries and software development kits (SDKs) receive continuous vendor security maintenance and performance upgrades directly from Google, ensuring native forward compatibility with future Android versions.
* **Preventive Maintenance Protocols:** Sustained platform reliability requires regular administrative upkeep, which involves monitoring monthly Firebase Blaze pay-as-you-go bandwidth consumption, renewing the Google Play Developer publishing credentials annually, and periodically confirming the integrity of automated daily Cloud Firestore backups. Scheduled quarterly maintenance sprints ensure that third-party library dependencies, security patches, and database indexing rules stay current.
* **Future Technological Enhancements:** Beyond its baseline operational lifecycle, the system is designed to accommodate advanced functional expansions currently documented in the project backlog. Prospective enhancements include: international GEDCOM 7.0 standard file interchange for two-way synchronization with global genealogical archives; on-device Google ML Kit Optical Character Recognition (OCR) for scanning physical PSA birth and parish marriage certificates; autosomal DNA centiMorgan (cM) correlation engines; and multi-clan federated tree merging with automated conflict resolution.

## Discussion

Empirical assessment of KinTrace through the **ISO/IEC 25010 Software Product Quality Model** yielded an exceptional composite mean of **4.72 out of 5.00**, affirming that the platform exceeds stakeholder standards across functional, security, and usability dimensions. When segregated across respondent cohorts, general Family Clan Members awarded a composite score of **4.76**, Clan Stewards provided a rating of **4.68**, and IT Experts recorded a rating of **4.71**. These consistently high scores demonstrate strong acceptance across both non-technical family users and technical evaluators.

Among the evaluated characteristics, **Reliability** achieved the highest individual rating with a score of **4.86 (Very High)**. Evaluators strongly praised the application's offline local caching resilience, which enables clan members to search records and explore complex tree visualizations even in areas without internet access, followed by automatic, conflict-free synchronization upon re-establishing a connection. **Functional Suitability (4.81, Very High)** and **Security (4.79, Very High)** also ranked prominently, validated by the flawless enforcement of biological cycle prevention, legal marriage consanguinity safeguards under Philippine civil law, botanical role permissions, and the automatic birthdate masking of living relatives.

Conversely, the lowest relative evaluation emerged within **Performance Efficiency on Clan Admin Operations**, which scored **4.52 (High)**, contrasted with 4.82 (Very High) among standard clan members. Qualitative evaluator comments noted that when navigating large lineage graphs containing more than 100 members on hardware-constrained smartphones, slight rendering latency occurred during fast multi-touch pinch-zoom gestures across dense generation tiers. Under **Usability and Interaction Capability (4.62, Very High)**, elder respondents recommended larger label typography on outer chart perimeters and simpler one-touch navigation triggers.

To resolve these evaluation findings, the researchers implemented targeted engineering optimizations in recent version increments. The team developed the **Adaptive 200-Member Horseshoe Fan Chart Growth Engine** (which dynamically expands radial world-space from 392px to 780px and switches crowded outer nameplates into single-line spokes clipped cleanly within slice boundaries), introduced lossless **800% Retina Vector Zoom**, added horizontal **Directory Filter Chips** with live record counters, and deployed the dedicated **1-Tap 'Trace Bloodline With...' Profile Shortcut** with auto-focus search.
